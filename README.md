Engineering Approach

I use this portfolio to demonstrate how I approach technical work:

Build systems in logical stages instead of treating tasks as isolated exercises.

Understand the business and security reason for a control before implementing it.

Use least privilege and separation of duties where practical.

Validate configurations with commands, logs, findings, and service health checks.

Document mistakes, failed approaches, corrections, and cleanup rather than hiding them.

Separate lab cost-saving decisions from production recommendations.

Use Infrastructure as Code and scripting when repeatability provides value.

Treat screenshots as evidence, not as a substitute for understanding.

Document how a lab implementation would be hardened or scaled in production.
